# VLESS через S3-хранилище (XDRIVE) — экспериментально

Новый транспорт Xray-core **XDRIVE** (v26.11.9, [XTLS/Xray-core#7231](https://github.com/XTLS/Xray-core/pull/7231), [#7352](https://github.com/XTLS/Xray-core/pull/7352)) передаёт трафик не напрямую, а через облачное хранилище. Клиент записывает зашифрованные сегменты в бакет S3, сервер их читает и пишет ответ туда же.

```
Клиент ──HTTPS──▶ storage.yandexcloud.net ◀──HTTPS── Ваш VPS ──▶ интернет
```

**Почему это может работать там, где остальное не работает:**
- клиент соединяется только с доменом облачного хранилища, а не с вашим VPS. IP сервера провайдер не видит, и заблокировать его нечем;
- автор бэкенда S3 проверял его на **Yandex Cloud и VK Cloud**. Это крупные российские облака, по сообщениям пользователей они доступны и при «белых списках» мобильных операторов. **В реальной сети это не проверялось**;
- серверу не нужны открытые порты, домен и даже публичный IP: он сам ходит в хранилище.

**Чем приходится платить:**
- задержка: в локальном тесте ~0.8 с на запрос, к реальному облаку добавится ещё сеть. Подходит для мессенджеров, сайтов и видео, но не для игр и звонков;
- нужен клиент на **Xray-core >= v26.11.9**, и версии клиента и сервера должны совпадать (транспорт новый, возможны несовместимые изменения). Ссылки `vless://` для XDRIVE нет, переносится JSON-конфиг целиком;
- **запросы к S3 платные.** В локальном тесте с настройками скрипта получилось около 0.4 запроса/с в простое и около 1.6 запроса/с при открытой сессии, плюс запросы на сами данные (~100 на 10 МБ). Цены сверяйте в [калькуляторе Yandex Cloud](https://yandex.cloud/ru/prices); новым пользователям даётся стартовый грант;
- в клиентском конфиге лежат ключи от бакета. Кто получил конфиг, тот может читать и писать в бакет.

## Установка (Yandex Object Storage)
1. В консоли Yandex Cloud создайте **отдельный** бакет (приватный, класс «Стандартное»).
2. Создайте сервисный аккаунт, выдайте ему роль `storage.editor` **только на этот бакет** и создайте статический ключ доступа (ID ключа и секрет).
3. Рекомендуется: в бакете добавьте правило жизненного цикла «удалять объекты старше 1 дня» — подстраховка, если сессия оборвётся и не удалит свои сегменты.
4. На VPS (можно на том же, где стоит autoXRAY, существующие конфиги не трогаются):
```bash
bash -c "$(curl -L https://github.com/vmhlov/autoXRAY/raw/refs/heads/main/test/xdriveS3-test.sh)" -- https://storage.yandexcloud.net ИМЯ_БАКЕТА ID_КЛЮЧА СЕКРЕТ
```
Для VK Cloud: `https://hb.ru-msk.vkcloud-solutions.com ИМЯ_БАКЕТА ID_КЛЮЧА СЕКРЕТ ru-msk`.

Скрипт:
- проверит ключи и бакет;
- поставит или обновит Xray;
- добавит inbound `vsXDRIVEs3`, проверит конфиг через `xray run -test` (при ошибке старый конфиг не меняется) и перезапустит Xray;
- **сам проверит туннель**: поднимет временного клиента и откроет сайт через бакет;
- сохранит клиентский конфиг в `/root/xdriveS3-client.json`.

Повторный запуск заменяет XDRIVE-конфиг новым (старые клиентские конфиги перестанут работать).

## Клиент
Импортируйте `/root/xdriveS3-client.json` как custom-конфиг в клиент с ядром Xray >= v26.11.9. Например, в v2rayN: обновите ядро Xray и выберите «Добавить пользовательский конфиг». Конфиг поднимает socks5 `127.0.0.1:10808` и http `127.0.0.1:10809`; российские сайты идут напрямую, реклама блокируется.

## Скорость или экономия
По умолчанию скрипт ставит экономный опрос `pollIntervalMs: 200`, `maxPollIntervalMs: 3000`. Если удалить эти два параметра в конфиге сервера и клиента, задержка уменьшится, но запросов станет примерно в 5 раз больше (в тесте ~7.8 запроса/с при открытой сессии).

## Удаление
Удалите inbound с тегом `vsXDRIVEs3` из `/usr/local/etc/xray/config.json` (до установки сохранена копия `config.json.bak-xdrive`) и выполните `systemctl restart xray`. Затем удалите бакет и ключ в консоли облака.
